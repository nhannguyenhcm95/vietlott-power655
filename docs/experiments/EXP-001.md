## 2. Targets, features and predictions

- Draws are ordered by draw_id. The loader guarantees contiguous ids 00001..N, so the draw index is t = int(draw_id).
- Target: y[t,k] = 1 if k ∈ S_t (main numbers only; the special number is not used), k = 1..55. Σₖ y[t,k] = 6.
- Secondary target: s_t = Σ_{k∈S_t} k (draw sum, §9.2).
- Features for draw t use only draws 1..t−1, so feature time (after draw t−1) < evaluation time (draw t).
  - n_t = t − 1
  - c_k(t) = #{u < t : k ∈ S_u}
  - m_t = min(W, n_t)
  - c_k^W(t) = #{t − m_t ≤ u ≤ t − 1 : k ∈ S_u}
- **B0:** p_k(t) = 6/55.
- **B1:** p_k(t) = 6·(c_k(t) + 1) / (6·n_t + 55).
- **B2(W):** p_k(t) = 6·(c_k^W(t) + 1) / (6·m_t + 55).
  - Short history: if n_t < W, all n_t draws are used, so B2 equals B1. At n_t = 0 both equal B0.
  - This case never occurs in a scored draw (t ≥ 501). It still must be tested.
- Reference implementation (vectorised; exact integer counts):
  - Y is the N×55 indicator matrix. C is the (N+1)×55 prefix sum, with C[0] = 0 and C[t] = Σ_{u≤t} Y[u].
  - Then c_k(t) = C[t−1, k] and c_k^W(t) = C[t−1, k] − C[t−1−m_t, k].
  - Probabilities are computed in float64 from the integer counts.
- **Fitted vs configuration (§7, §8.3):**
  - B0, B1 and B2 have **no fitted quantity**. The counts are features, and they use all draws < t, including earlier draws of the same fold's scored horizon.
  - α and W are configuration. W is chosen only by the rule in §4.
  - So the prediction for draw t does not depend on the fold, and the §8.4 refit is a no-op.
  - The per-fold scores are a partition of one prediction series over 00501–01190.
- Σₖ p = 6 exactly in exact arithmetic for B0, B1 and B2. The evaluator never renormalises.
- 0 < p < 1 always. The smallest possible scored p is 6/3055, from B1 with n_t = 500 and a zero count. The largest is 6·51/355 ≈ 0.862, from W = 50 with a count of 50. So the [1e−6, 1−1e−6] clip is never active, and n_clipped is expected to be 0.
- The special number, dates, weekday and jackpot are not used.

## 4. Configuration choice (§7, §8.3)

- **Family (1), B1:** a single configuration, so it is the finalist by definition. It goes to M6 whatever its validation score.
- **Family (2), B2:**
  - For each candidate W, compute L_W = the mean per-draw log loss over the 210 validation draws.
  - Let L* = min_W L_W and T = {W : L_W − L* ≤ 1e−12}. The selected value is **W\* = max(T)**.
  - Ties are measured against the minimum, not chained between candidates. This reading of the frozen §7 text is recorded in TASKBOARD "M5 records" (§7 tie rule, audit finding 4). SPECIFICATION is not edited.
  - No other quantity influences W\*. That includes Brier, ECE, folds 1–9 and any CI.
- EXP-001 **proposes** the B1 and B2(W\*) finalists. They become frozen only when the Project Lead records them under TASKBOARD "Decisions" at the M5 finalist freeze (§8.3), together with the spec sha256. W\* is then frozen through M6.
- Finalist validation scores are labelled `selection_biased`. This applies to B2(W\*), and also to B1 with the note
  `selection_biased: true (§8.3 label; B1 has no within-family choice)`, written into metrics.csv and summary.md.

## 5. Metrics (§9) and bootstrap (§9.3)

Metrics are computed for every period × configuration. Let P be the clipped p.

- **Per-draw log loss (primary):** LL(t) = −(1/55) Σₖ [y ln P + (1−y) ln(1−P)], clipping to [1e−6, 1−1e−6]. The number of clipped cells is reported.
- **Per-draw Brier score:** BS(t) = (1/55) Σₖ (y − p)², computed on the unclipped p.
- **Σp:** Σₖ p per draw; the mean, min and max are reported.
- **ECE and reliability table:** these pool all (t, k) cells of the period.
  - The bin edges are `np.unique(np.quantile(p, [0.1, …, 0.9]))` with the default linear method. Each cell's bin is `np.searchsorted(edges, p, side="right")`.
  - Empty bins are dropped. ECE = Σ_b (n_b/N)·|ȳ_b − p̄_b|.
  - The number of non-empty bins is reported. With tied p this can be fewer than 10. B0 has one bin and ECE = 0, which is **not** evidence of calibration.
- **Set-level log score:** B0 only, −ln P(S_t) = ln C(55,6) = 17.182450.
  - B1 and B2 are marginal-only models, so they have no joint distribution. They are reported as `NA (marginal-only)`.
  - The product of their marginals must not be used as a set probability.
- **Sum forecast (secondary, §9.2):**
  - B0 forecasts ŝ = 168. B1 and B2 forecast ŝ(t) = Σₖ k·p_k(t). This is a forecast of the **mean** draw sum, the expectation implied by the marginals.
  - RMSE of s_t − ŝ(t) is the loss that matches a mean forecast. MAE is reported as **descriptive only**, because the mean is not the MAE-optimal point forecast.
- **Paired differences vs B0:** ΔLL, ΔBS, ΔMAE and ΔRMSE, where Δ = config − B0.
  - Because B0's LL and BS are constant, ΔLL and ΔBS are shifted copies of the configuration's own series. This is expected (§9.3).
- **Bootstrap:** a circular block bootstrap over draws (all 55 cells of a draw kept together). It is run separately for each period.
  - Each period uses **a fresh `default_rng(20260924)`**.
  - One index matrix per period is shared by all five configurations, which makes the comparisons paired.
  - The indices are generated exactly as follows:
    ```
    nb = ceil(n / 10); starts = rng.integers(0, n, size=(10000, nb))
    idx = ((starts[:, :, None] + np.arange(10)) % n).reshape(10000, nb * 10)[:, :n]
    ```
  - Each resample recomputes every metric: mean LL, mean BS, ECE (with bins recomputed), MAE, RMSE, and each Δ.
  - The CI is the two-sided 95% percentile interval, `np.percentile(stats, [2.5, 97.5])`.
  - No p-values are computed. Development CIs are descriptive only; no hypothesis is decided in M5 (§9.3).

## 9. Expected values under the null (sanity references; never targets)

H1/H3 null: draws are i.i.d. uniform 6-of-55, so y[t,·] is independent of history with mean p0 = 6/55.

- **B0 is constant per draw:** LL = 0.344610, BS = 0.097190, set-level 17.182450, ECE = 0.
- **Brier excess is exact in expectation:** with m history draws, E[ΔBS(t)] = 36·m·p0(1−p0)/(6m+55)².
  - B2: W=50 ≈ +0.00139; W=100 ≈ +0.00082; W=200 ≈ +0.00044.
  - B1: ≈ +0.00019 at n=500, falling to ≈ +0.00008 at n=1189.
- **Log-loss excess (exact):**
  - Formula: E[ΔLL(t)] = Σ_{c=0..m} Bin(c; m, p0)·[CE(p0, p̂(c)) − H(p0)], where p̂(c) = 6(c+1)/(6m+55),
    CE(p0, q) = −p0 ln q − (1−p0) ln(1−q) and H(p0) = CE(p0, p0). It is computed with `scipy.stats.binom.pmf`.
  - A period's reference is this value averaged over the period's scored draws, with m = min(W, t−1) for B2 and m = t−1 for B1.
  - B2 (m = W for every scored draw): W=50 → +0.00788; W=100 → +0.00445; W=200 → +0.00236.
  - B1: +0.00098 at n=500 and +0.00042 at n=1189. The average is +0.00062 over dev_pooled and +0.00046 over validation.
  - These match the auditor's values and my independent computation. For intuition only, a second-order expansion gives
    ≈ 18m/(6m+55)². It is not used as a reference.
- **Null simulation (TASKBOARD "M5 records"; 3000 histories of 1190 draws):**
  - W\* = 200 in all 3000. **Any other W\* triggers a bug and leakage check first. It is not a finding.**
  - B1 < B0 on validation LL in about 4% of null histories.
  - My independent check (1000 histories, seed 7) gave W\* = 200 in 1000 of 1000 and B1 < B0 in 4.5%.
- **Implications:**
  - Under the null, every B1/B2 configuration is expected to score slightly *worse* than B0, and B1 is expected to be the closest.
  - A realised Δ < 0 on development data is not evidence against the null. For B1 on validation it happens about 4% of the time by chance.
  - A large departure from these references in either direction is a trigger to check for leakage or a bug first. It is not a finding.
- The recorded summary reports the observed values next to these references. **Nobody adjusts code, α, the W set or the periods to move the observed values toward or away from them.**

## 13. Non-goals

## 14. Limitations

- Every development draw (00001–01190) was already seen descriptively in M3 and M4, so validation is exposed (§8).
- LL and Brier assess marginals only. Within-draw dependence is not scored, and B1/B2 have no set-level score.
- Per-fold CIs rest on 4–5 blocks of length 10, so they are very rough and descriptive.
- Fold scores for B0–B2 are a partition of a single prediction series. They are not independent replications.
- Only M6 (01191–01401, run once) can decide H6.
