## Rulings on the implementer's choices

- **(a) C2 uses the first n' specials of each FRESH replicate. Accepted.** FRESH specials are i.i.d. uniform on 1..55 across draws, so the first n' form an exact null sample for n' draws. n' = n today (TASKBOARD E1).
- **(b) Open-ended §6.4 items deferred to the M3 outputs. Accepted, with a condition.** The manifest must list exactly which §6.4 items were computed and which were deferred. "Sum χ² on the M3 bins" is concretely specified, so compute it (n9) rather than defer it. Nothing deferred may later be promoted to a claim.
- **(c) Stream 103 for conditional H2. No collision.**
  - Registered streams: M3 uses 1 and 2; M4 uses 101, 102, 1101 and 1102. Test streams (7xx, 9xxxxx, 999001, 12345) are disjoint.
  - It draws uniform 1..49 directly instead of calling the FRESH simulator. That is distributionally identical: under the mechanism the special is uniform over the 49 numbers not drawn as main.
  - Accepted. The manifest already records 103 and R = 2000. Register 103 in SPECIFICATION §6.4 at the next change-controlled revision; do not edit the approved v1.2.1 now.

## Findings

**M1 — MAJOR — follow-up gating is not labelled, and the summary contains a false statement.**
- §6.3 requires non-interpreted follow-up tables to be labelled "parent not rejected; not interpreted". The ten `m4_followup_*.csv` files have no such column. Their headers are `number,count,n,p_null,p_raw,p_holm,…`, which invites reading p_holm per number.
- The LIMITATION line "per-number follow-up counts are reported only when the parent test rejects" is untrue: C1 and C2 per-number follow-ups are always written.
- Fix:
  - Add a column `interpretation` = `parent not rejected; not interpreted` or `parent rejected (p_holm=…)` to every follow-up CSV, and a matching line per parent in the summary.
  - Correct the limitation text.
  - Test that every follow-up row carries the label, and that the label switches when a synthetic parent rejects.

**M2 — MAJOR — the §6.5 per-test reporting is incomplete, and the summary layers are empty or wrong for the non-rejection case.**
- Missing per test: n (and N = 6n for C7), the **replicate mean of T** (a key sanity check: C1 ≈ 49, C2 ≈ 54, C7 ≈ 392, C8 ≈ 42), and CIs where §6.2 defines them:
  - C3: per-lag Ō_j − 36/55 ± 1.96·√(0.529146/(n−j)).
  - C5: r_h with ±1.96/√n.
  - C1: the Wilson CIs per number. Citing `outputs/eda/through_01190/number_frequency.csv` is acceptable, because it has the same range and definitions.
- Effect sizes exist only as a JSON string in `m4_results.csv`.
- **OBSERVED** has no observed values. Put the effect sizes there, with templated sentences and no numbers named.
- **INTERPRETATION** only covers rejections. For zero rejections it must say, as fixed template text:
  - no confirmatory evidence against H1–H5 on 00001–01190 at FWER 0.05;
  - non-rejection is not proof that the nulls hold;
  - the smallest raw p values do not survive the pre-registered multiplicity control (C9, C13 about 0.02; Holm about 0.26–0.28). About 1 − (1 − 0.023)^13 ≈ 0.26 of null families have a raw p this small somewhere.
- Fix: expand `m4_results.csv` and the summary template accordingly, and test that each column and section is present.

**M3 — MAJOR — the §6.5 calibration acceptance test is missing.** This covers 400 FRESH datasets, n = 300, inner R = 199, proportional synthetic years; each C-test must reject in [0.0175, 0.090] and the Holm FWER must be ≤ 0.090, with a fixed seed. It is in progress. PASSED requires it to be green. A failure means an investigation, never a seed change.

**m4 — MINOR — C11–C13 cells are hardcoded instead of pooled by the §6.2 rule.** At n = 1190 this changes nothing. At the replication n = 211, the odd/low cell 0/6 has n·P = 2.15 and consecutive ≥3 has 1.47, both below 5. So the replication would violate "tail cells merge inward until n·P ≥ 5". Fix: derive the cells from the null pmf and n with the M3 pooling helper (after the M3 R1 fix), and add a test at n = 211.

**m5 — MINOR — the escalation branch reports the wrong decisions.** When escalation triggers, §6.1 says the R = 100,000 values are final. The summary INTERPRETATION still counts rejections from the R = 10,000 table, and the decision column is not marked superseded. Fix: take decisions from the escalated table and label the first run "superseded by escalation". Test with a forced trigger (a small R and a monkeypatched family).

**m6 — MINOR — C13 cell probabilities are hardcoded to 6 decimals.** The statistic differs by 1.46e-4 from the exact value. The p value stays valid, because the replicates use the same constants, but §6.1 says exact references. Fix: use `null_reference.consecutive_pairs_pmf()`. This slightly changes the C13 statistic, and its p may move by MC-noise size. It is declared here, before the rerun, as a spec-conformity correction.

**n7 — NIT.** In `build_observed`, the "years are not contiguous" check compares Σ group sizes with n, which is always true. Replace it with a check that the year is non-decreasing in draw order. It holds on the real data, as checked.

**n8 — NIT.** In the manifest, record `frozen_dataset_version: ds_cbdf3834368e` and the `frozen_prefix` result next to `source_dataset_version`, so readers see why the source hash differs (live draw 01402).

**n9 — NIT.** Exploratory items:
- Add asymptotic χ² p for Q(5) and Q(20).
- Compute "sum χ² on the M3 bins" (FRESH p on a registered exploratory stream, e.g. 104), or list it explicitly as deferred in the manifest.
