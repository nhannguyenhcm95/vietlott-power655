## 1. `reconcile.assess_reconcile.blocking_ids` bug fix

**Before (reviewed and passed under M2-T2):**
```python
blocking_ids = unaccepted_mismatch_ids & set(published_ids or set())
```
**After (current):**
```python
about_to_be_published = rep.left_ids - set(published_ids or set())
blocking_ids = unaccepted_mismatch_ids & about_to_be_published
```

**Ruling: the old code was backwards, and the fix is correct.**

- Design §1.1 defines `blocking_ids` as `unaccepted_mismatch_ids ∩ the set about to be published`.
- Design §2.1 step 4 defines "the set about to be published" explicitly as *"official staging ids minus the draw_ids of `read_fact_draw(curated)`"* (also cross-referenced by D2 and re-audit N7).
- The old code intersected with `published_ids` itself (the ids **already** curated) — the complement of what the design specifies. That would have blocked curate on a mismatch involving an *already-published* draw (the design's explicit non-blocking case, §2.2's "realistic mismatch" row) while *failing to block* on a mismatch confined to a genuinely unpublished draw whose id also happens to not be in `published_ids` for unrelated reasons — in short, backwards relative to D2's intent.
- The new code computes `rep.left_ids - published_ids` (official ids not yet curated) first, then intersects with the unaccepted mismatch ids — this is exactly "official staging ids minus the draw_ids of `read_fact_draw(curated)`", matching §2.1 verbatim.

**Impact on my earlier M2-T2 review: none.** `blocking_ids` is consumed only by `src/ingestion/refresh.py` (M2-T3, step 4's curate gate); grep confirms no other production code or M2-T2 test reads `assessment.blocking_ids`. `check_reconcile_sources` in `src/reporting/data_quality.py` calls `assess_reconcile` but only uses `.status`, `.findings`, and `.mirror_lag_draws` — never `.blocking_ids`. My M2-T2 real-data verification also never exercised this field: KI-001 is the only known accepted mismatch/lag on real data, and there were zero unaccepted `reconcile.field_mismatch` findings, so `blocking_ids` was empty either way. **No M2-T2 PASSED output or acceptance-criteria check depended on the buggy formula.**

**Test coverage of the fix.** `tests/test_refresh.py::test_realistic_mismatch_2000_then_0830_not_blocked_exit30` pins exactly the required realistic sequence: an official-only publish of 00006 at 20:00 (`curate_action == "rebuilt"`), then a mirror mismatch on the now-already-published 00006 at 08:30 next day — asserts `exit_code == 30` (report FAILs `reconcile.field_mismatch`) but `curate_action in ("unchanged", "rebuilt")`, i.e. **not** `"blocked"`. The complementary case, `test_mismatch_on_unpublished_draw_blocks` (both sources gain 00006 in the same run and disagree before it is published), asserts `curate_action == "blocked"` and the curated version is unchanged. Both pass.

## 3. Network isolation

- **Code reading.** `src/api/http_client.py`'s `HttpClient` only opens a real `requests.Session()` when no `session=` is injected. Every source built by test fixtures goes through `tests/conftest.py:make_client()`, which always injects a `FakeSession`/`RoutingSession` (scripted responses, no sockets). `tests/conftest.py:refresh_source_factory()` (used throughout `tests/test_refresh.py`) builds sources exclusively via `make_official_source`/`make_mirror_source`, both of which call `make_client(...)`.
- Every `main(["refresh"], ...)` call in `tests/test_refresh.py` that could reach `get_source` (and thus a real `HttpClient`) first monkeypatches `src.cli.get_source` to `refresh_source_factory(...)` (`test_internal_error_exit50_lock_released`, `test_refresh_logging_events`, `test_cli_uses_injected_paths`). The two calls that don't patch it (`test_lock_held_exit40_no_source_calls`, `test_exit40_does_not_touch_alert`) hold the lock first, so `main` returns 40 from the lock-acquisition failure path in `src/cli.py` **before** `get_source` is ever called — confirmed by reading `src/cli.py:97-107`, which is entered before the `args.cmd == "refresh"` branch. `test_refresh_as_of_in_past_rejected_without_injection` calls `main(["refresh", "--as-of", ...])` with no injected `paths`; the `--as-of` guard (`src/cli.py:89-93`) raises `parser.error(...)` → `SystemExit(2)` before logging setup, lock acquisition, or any source call.
- `src/cli.py`'s comment at line 173-174 confirms the design intent explicitly: `get_source` is looked up in the CLI (not via `run_refresh`'s own default) specifically so tests can monkeypatch `src.cli.get_source`.
- **Independent verification.** I ran the full suite with `socket.socket` monkeypatched (before pytest collection) to raise on any instantiation attempt, outside of any repo file (a throwaway script, not committed):
  ```
  python -c "import socket; socket.socket = <raises-on-init>; import pytest; pytest.main(['tests/'])"
  ```
  Result: **219 passed**, 0 failed — including all of `tests/test_refresh.py`, `tests/test_lock.py`, and `tests/test_scripts.py`. This is strong independent confirmation that no test opens a real network socket.

## 4. Exit codes and failure semantics (D1, §2.2, §2.3)

- `src/ingestion/refresh.py:_compute_exit_code` implements exactly the D1 precedence `50 > 30 > 10 > 0`: `50` if `overall_status` is missing/invalid (report step failed or produced nothing — matches "no report was written"); else `30` if `overall_status == "FAIL"`, or `official_status in ("failed", "empty")`, or `curate_action in ("blocked", "failed")`; else `10` if `overall_status == "WARN"`; else `0`. Exit `40` is never returned by `run_refresh` — it is CLI-only, from `src/cli.py`'s `LockHeldError` handler, consistent with §2.3 ("40 applies on its own").
- Official empty fetch: `_ingest_status` maps a `success` status with `rows_received == 0` to `"empty"`, which `_compute_exit_code` routes to 30. Verified by real code and by `test_official_empty_fail_exit30` (exit 30, `official_status == "empty"`, curated untouched).
- `mirror_shrink` stays WARN, unchanged from the M2-T2-reviewed report code; `test_mirror_shrink_warn_exit10` confirms `run_refresh` surfaces it as exit 10 / `overall_status == "WARN"` end-to-end through the refresh pipeline (D7 confirmed by the human, re-audit N1).
- Every one of `run_refresh`'s 5 numbered steps (official, mirror, reconcile, curate, report) is wrapped in its own `try/except Exception`, each appending to a shared `messages` list and logging via `log.exception(...)` without aborting the remaining steps — matches §2.1's "each numbered step is wrapped in try/except Exception."
- Exit-40 semantics: `src/cli.py`'s `LockHeldError` branch calls `append_locked_refresh_log_row(paths, ...)` (only for `cmd == "refresh"`) and returns 40 **without** calling `_write_alert`/`_clear_alert` — ALERT.txt is untouched. `append_locked_refresh_log_row` writes a row with `exit_code=40` and all run columns empty. Confirmed by `test_lock_held_exit40_no_source_calls` (asserts the refresh_log row has `exit_code == "40"` and an empty `official_run_id`, and that `ingestion_log.csv` bytes are unchanged — no source was called) and `test_exit40_does_not_touch_alert` (a pre-existing ALERT.txt sentinel is untouched).
- ALERT.txt lifecycle: `run_refresh` writes `"started, not finished <refresh_id> <started_at>"` at the very start (step 0), and at the end either clears it (`exit_code == 0`) or replaces it with the final cause + report path + message (`exit_code != 0`). Confirmed by `test_alert_started_then_final_then_cleared`, which captures the alert content mid-run via a source spy and checks both the in-progress and final/cleared states.
- Stale-lock break: `src/ingestion/lock.py:RunLock.acquire()` uses `os.replace(self.path, stale_target)` to atomically move the stale lock aside before retrying the `O_CREAT|O_EXCL` create once; a `FileNotFoundError` on the replace, or a `FileExistsError` on the retry, both raise `LockHeldError` (the race-loser path). Matches §2.4 exactly, including "never use `os.kill(pid, 0)`" (not used anywhere in the file). Confirmed by `tests/test_lock.py::test_stale_lock_broken_and_logged` and `test_stale_lock_break_race`.

## 5. Atomic writes / manifest-last

`src/ingestion/loader.py:_atomic_write_bytes` writes to a `.tmp` file then `os.replace`s it into place, retrying a `PermissionError` up to 3 times with 1s sleeps before re-raising — matches §1.2/finding 14 exactly. `build_curated` writes `fact_draw.csv`, `fact_draw_number.csv`, `dim_number.csv` first (each via `_atomic_write_csv` → `_atomic_write_bytes`), then `dataset_manifest.json` **last**, so the manifest remains the commit marker (a failure partway through leaves the old manifest, and thus `curated_matches_staging`, pointing at the previous consistent state).

**Independent verification (temp copy, not real `data/`):** copied `data/staging/` into an isolated temp path and called `build_curated(Paths(root=tmp, data=tmp), "vietlott_official")`. Result: `fact_draw.csv`, `fact_draw_number.csv`, and `dim_number.csv` are **byte-identical** to the real `data/curated/` files (147030, 281484, 1069 bytes respectively — exact match), and the manifest matches field-for-field except `built_at` (expected, since it's a fresh timestamp). This confirms the atomic-write refactor is behaviour-preserving: same bytes as before.

Also directly tested: `test_curated_manifest_written_last` (injects a failure while writing the 2nd curated file via a monkeypatched `_atomic_write_csv`, asserts `curate_action == "failed"` and the old manifest bytes are unchanged) and `test_permission_error_retried_then_failed` (injects `PermissionError` on `os.replace` for curated writes, asserts exactly 3 retries with 1s sleeps before giving up).
