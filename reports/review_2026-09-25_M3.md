## Rulings on the self-reported decisions

1. **Tail pooling (two-pointer scan).** The pooling depends only on the null pmf and n. `_pool_cells` never sees observed data, so that part is fine. **It does not meet the spec invariant** "every cell n·P ≥ 5": see F1. Not accepted as is.
2. **`n_special` kwarg.** Accepted. It is exactly what Rev 3.1 E3 requires. It is not a code-path no-op: `build_eda` passes `n_nonmissing`, which equals n today because TASKBOARD E1 records 0 missing specials. It needs a test with n' < n (F7).
3. **No separate D6 template in the summary.** Accepted, because §5 lists *allowed* templates, not mandatory ones. However, the per-metric line is labelled plain `gap:`, and the fixed limitation "Gaps are memoryless" refers to inter-arrival gaps. A reader will conflate the two. Relabel the line (F6).

## Findings

**F1 — MAJOR — the pooling invariant is violated at the real n.**
- Evidence: I ran `_pool_cells` on the null pmfs, with no data.
  - n = 1190: `sum <=70` has n·P = 3.58, and `min_gap >=8` has 1.59.
  - n = 980: `sum >=261` has 4.78, and `max_gap <=5` has 4.23.
- Cause: the scan absorbs units by their *own* probability, but it never checks that the pooled tail itself reaches 5.
- T13 checks only `min_pmf`, so it passes.
- Fix:
  - After the scan, while a pooled tail has n·P < 5, absorb the next inward unit.
  - If the two tails meet, emit one cell.
  - Extend T13 to all 10 metrics at n ∈ {980, 1190, 300, 60}. Use n_obs = 5n for `gap`.
  - Regenerate the real outputs.
- This is an implementation fix toward a rule written before any data was seen, not a method change.

**F2 — MAJOR — the sum histogram and the distribution table are in lexicographic, not numeric, order.**
- Evidence (`cell` labels only): the sum rows run `101-110 … 251-260, 71-80, 81-90, 91-100, <=70, >=261`, and `max_gap` rows run `10 … 33, 6, 7, 8, 9, <=5, >=34`.
- Cause: `draw_metric_distribution` sorts on the string `cell`.
- `draw_sum_chart` plots in table order, so `draw_sum.png` has a scrambled x-axis.
- In `draw_min_max_range_chart`, `to_numeric("<=19")` is NaN, so the pooled lower tail of max and range is drawn at the right end.
- Spec §5 requires rows sorted by key (value).
- Fix:
  - Keep an integer `lo` column (or a hidden sort key), and sort by (metric order, lo).
  - Charts plot in table order, with no per-chart re-sorting.
  - Add a test that within each metric `lo` is strictly increasing, and that the first/last pooled cells are `<=`/`>=`.

**F3 — MAJOR — T8(a)/(b)/(g) does not meet its acceptance criterion.** `test_t8g_dataset_version_metadata_only`:
- compares variant a with variant b, not with the clean fixture (`clean_990` is unused);
- recomputes `dataset_version` over *all* rows, so the column changes with post-cutoff content. T8(g) requires it to stay constant;
- has to drop `source_dataset_version` to pass;
- compares only CSV frames, not bytes, and skips `eda_summary.md` and the manifest;
- never asserts T8(c) (no output draw_id > cutoff) on a run with later rows present.

Fix:
- Build three fixtures with the same first 10 rows and one constant `dataset_version` column: clean (10 rows); (a) with a different valid tail; (b) with invalid tail rows (number 99, an empty main cell, a non-numeric cell).
- Assert that every CSV, `eda_summary.md` and `eda_manifest.json` has the same sha256 as the clean run, and PNGs too within one environment.
- Assert that no draw_id in any output exceeds the cutoff.

This test would have caught F4.

**F4 — MINOR — post-cutoff content can change `analysis_version` for the analysis rows.**
- Evidence: I made a synthetic 11-row fixture with an empty `n1` in row 11. With `--through-draw 00010`, `analysis_version` changes from `ds_473ac8e2dceb` to `ds_fbaa31970c84`.
- Cause: pandas reads the whole column as float64, and `tables.dataset_version` serialises `5.0`.
- It is also true that a malformed post-cutoff `draw_id` would crash the `astype(int)` filter.
- Curated data passes the M2 rules, so this is unlikely in practice. It still breaks §1.3/§1.4.
- Fix:
  - After filtering, cast `MAIN_COLS` to int64 and `special_number` to Int64 before validation and hashing.
  - Filter with `pd.to_numeric(draw_id, errors="coerce")` or a 5-digit string compare.
  - Cover both with F3's fixtures.

**F5 — MINOR — two tests are vacuous.**
- `test_t13_pooling_identical_for_same_n_different_draws` calls `_pool_cells` twice on the same input, so no observed data is involved.
- The E_g check in `test_t6_interarrival_gaps_hand_fixture` asserts only `expected_formula >= 0` and never calls `interarrival_gaps`.
- Fix:
  - Run `draw_metric_distribution` and `interarrival_gaps` on two different fixtures with the same n, and assert identical `cell`/`null_prob`/`expected_count` columns.
  - Check `interarrival_gaps` expected counts against a null simulation. Suggested: n = 300, R ≥ 300, stream fixed, |sim − E_g| < 4 MC-SE for g ≤ 20.

**F6 — MINOR — summary labelling.**
- (a) The `gap:`, `max_gap:` and `min_gap:` lines should read `within_draw_gap (D6):` etc., and the limitation should read "Inter-arrival gaps are memoryless under the null."
- (b) The main-number and special-number lines are identical in form ("… of 55 numbers …"), so a reader cannot tell which is which. Prefix `main:` and `special:`.
- Both need a small template/fixed-line update. I will make it as spec Rev 3.2 (§5) together with this rework, and the regexes and T11 whitelist then follow.

**F7 — MINOR — the special-number MC band and stream registration.**
- `n_special` has no test with n' ≠ n. Add one: with n' < n, the special quantiles move and match Binomial(n', 1/55) min/max quantiles within MC error.
- The special numbers are simulated on stream 2 as separate draws. That is marginally correct, but the spec registers only stream 1, and SPECIFICATION §6.1 says "M3 uses stream 1".
- No code change needed: I will register stream 2 in M3 spec §3.2 (Rev 3.2). SPECIFICATION's M4 streams 101/102 do not collide.

**F8 — MINOR — the pooled within-draw gap band is labelled `exact` but is approximate.**
- For `gap`, the band and "expected outside" use Binomial(5n, P).
- The 5 spacings of a draw are dependent (they sum to ≤ 54), so a cell count is not binomial. The pmf and the expected counts are exact; the band is not.
- Fix: set `reference = "exact_pmf_approx_band"` for metric `gap`, or derive the band from the MC replicates.
- This is also a gap in my spec's §3.1 wording, which I will fix in Rev 3.2.

**F9 — MINOR — the T11 chart-title check is weak, and captions omit R and seed.**
- The regex matches only plain `set_title("...")` literals. It misses f-strings (the rolling title) and variable titles.
- Spec §0 requires MC captions to state `MC(R, seed)`. The charts say only "null: MC".
- Fix:
  - Collect titles from the rendered figures (`fig.axes[*].get_title()`, `fig._suptitle`) during a fixture run.
  - Append `MC(R=…, seed=…)` to the MC-based chart titles.

**NIT-1.** Refusal cases other than "no override" lack the `read_fact_draw` spy and the "no files written" check. `eda_ceiling_refused` and `eda_spec_not_approved` are never asserted (use `caplog`). T8(e) "non-existent" is tested only with `999999`, which fails the format check; add `00011` against a 10-row fixture.

**NIT-2.** T10 skips PNG hashes. The spec requires them to be identical within one environment.

**NIT-3.** The `sim_lo`/`sim_hi` quantiles of integer statistics use linear interpolation. Use `method="lower"`/`"higher"` so the bands are integers.
